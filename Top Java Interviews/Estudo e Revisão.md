6. Why people say that Java is 'write once and run anywhere' language?
We can write Java code on Windows and compile it in Windows platform. The class and *jar* files that you get from Windows platform can run as it is on  Unix environment. So it is a truly platform independent language.

Behind all this portability is Java byte code. Byte code generated by Java compiler can be interpreted by any JVM. So it becomes much easier to write programs in Java and expect those to run on any platform. 

Java compiler javac compiles java code and JVM java runs that code.

*Por que o Java é conhecido como uma linguagem "write once, run anywhere"?*

**C)** Porque o Java só funciona em sistemas Windows e Linux.
**D)** Porque o Java é uma linguagem de baixo nível.
?
**B)** Porque o Java compila o código para bytecode, que pode ser executado em qualquer JVM.

Em aplicações Java, o termo #packing se refere à forma como projeto é empacotado e distribuído para execução. Os dois formatos mais comuns são **JAR (Java ARchive)** e **WAR (Web Application ARchive)**. 

**JAR (Java ARchive)** é um arquivo compactor (similar a um .zip) que contém todas as classes compiladas (.class), bibliotecas externas e metadados necessários para executar uma aplicação Java. 
É amplamente utilizado em **aplicações standalone** (indepententes) e, com o **Spring Boot**, também em **aplicações web modernas**.
Pode ser executado diretamente com o comando: *java -jar application-name.jar*.
Inclui um servidor web embutido (como Tomcat, Jetty ou Undertow).
Facilita a implantação em **nuvem** e **contêineres Docker**, já que o pacote é autocontido.
Ideal para **arquitetura de microsserviços**, onde cada serviço é independente.

**WAR** é um pacote projetado para aplicações web **tradicionais**, que precisam ser implantadas dentro de um **servidor de aplicação externo**, como:
- Apache Tomcat
- WildFly/JBoss
- GlassFish

**Vatagens:**
- útil em ambientes corporativos legados, onde há um servidor centralizado que gerencia múltiplas aplicações;
- permite configurações específicas de servidor e integração com recursos empresariais (como EJB, JNDI etc).
